# 启元农链 — 目录重构方案、模块说明与上手路径

> 面向：多人协作、持续集成（CI）的混合型项目（Spring Boot + Vue + IoT）。  
> 仓库现状摘要：后端与若依二开在 `apps/qiyuan-backend/`（`ruoyi-admin`、`ruoyi-system` 等）；**管理端前端**在 **`frontend/admin-web`**（阶段 B 由原 `ruoyi-ui` 迁入）。设计/计划类文档在 `docs/`，基线 SQL 在 `db/baseline/`；协作约定见根目录 `CLAUDE.md`。

> **迁移状态**：阶段 A 与阶段 B **已在主分支完成**。下文 §1.3 中的 `git mv` 命令块仅作**历史对照**，新克隆仓库请勿再执行，以免破坏路径。

## 1. 理想的根目录重构方案

### 1.1 设计原则


| 原则           | 说明                                                                         |
| ------------ | -------------------------------------------------------------------------- |
| **单仓单体优先**   | 后端为 Maven 多模块；前端为 `frontend/admin-web` 独立 npm 工程（包名仍为若依默认 `ruoyi`）。     |
| **文档与代码分离**  | 所有产品/联调/设计文档进 `docs/`，避免与可执行代码混在根目录。                                       |
| **数据库脚本版本化** | SQL 统一进 `db/`，区分基线、增量、种子数据。                                                |
| **IoT 可复现**  | EMQX、规则示例、本地 docker-compose 进 `iot/` 或 `deploy/local/`，与业务代码解耦。            |
| **CI 入口清晰**  | `.github/workflows/` 或 `ci/` 中按 `backend` / `frontend` / `db-check` 分 Job。 |

## 2. `apps/qiyuan-backend`（若依）子模块职责与农业业务代码放置

### 2.1 典型子模块职责（与本项目 `pom.xml` 一致）


| 模块                  | Maven artifact    | 职责                                                                                                                     |
| ------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **ruoyi-common**    | `ruoyi-common`    | 通用常量、异常、`AjaxResult`、`BaseEntity`、工具类、注解等；**无业务**，尽量不依赖 Spring Web 复杂栈。                                                |
| **ruoyi-system**    | `ruoyi-system`    | 领域与持久化：**实体、Mapper、Service 实现**；若依自带的 `Sys`* 与你们已存在的 `Agri`* 业务表、MyBatis XML 多在此模块。                                    |
| **ruoyi-framework** | `ruoyi-framework` | 安全、拦截器、数据源、Redis、全局异常、权限解析等 **Web 框架层**；依赖 `ruoyi-system`。                                                             |
| **ruoyi-quartz**    | `ruoyi-quartz`    | 定时任务定义与调度相关代码。                                                                                                         |
| **ruoyi-generator** | `ruoyi-generator` | 代码生成器（Velocity 模板等），偏研发效率工具。                                                                                           |
| **ruoyi-admin**     | `ruoyi-admin`     | **Spring Boot 启动入口**（`RuoYiApplication`）、`Controller`、对外 REST、Swagger 配置；依赖 `ruoyi-framework`，并通常再依赖 quartz、generator。 |


**依赖关系（简图）：**

```text
ruoyi-admin
    └── ruoyi-framework ──? ruoyi-system ──? ruoyi-common
    └── ruoyi-quartz ─────────────────────? ruoyi-common
    └── ruoyi-generator ───────────────────? ruoyi-common
```

### 2.2 农业业务新代码应放哪里？


| 层次                            | 放置位置                               | 说明                                                                 |
| ----------------------------- | ---------------------------------- | ------------------------------------------------------------------ |
| **Controller**                | `ruoyi-admin/.../controller/agri/` | 与现有一致：HTTP 入参、权限注解、`startPage()` 分页。                               |
| **Service / Mapper / Domain** | `ruoyi-system/...`                 | 与现有一致：`domain`、`mapper`、`service`、`resources/mapper/system/*.xml`。 |
| **跨模块复用的纯工具**                 | `ruoyi-common`                     | 无状态工具、与业务无关的通用模型。                                                  |
| **安全、过滤器、第三方 Bean 装配**        | `ruoyi-framework`                  | 谨慎修改，避免与若依升级冲突。                                                    |


### 2.3 是否新建 `ruoyi-agribiz` 模块？


| 策略                            | 适用场景                                                                                                                |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **维持现状（推荐短期）**                | 团队规模小、`Agri`* 与 `Sys`* 已在 `ruoyi-system`；减少 POM 与包扫描调整成本。                                                           |
| **新建 `ruoyi-agribiz`（推荐中长期）** | 农业子域很多、希望 **编译隔离**、单独测试、或未来拆微服务；`ruoyi-agribiz` 仅依赖 `ruoyi-common`，`ruoyi-system` 若仍需共用基础表则通过 **API 或保留共享模块** 设计边界。 |
| **折中**                        | 在 `ruoyi-system` 内用包名划分：`com.ruoyi.agri.`* 与 `com.ruoyi.system.`*，为将来抽模块预留。                                         |


新建 `ruoyi-agribiz` 时需：`parent` 指向根 POM、在根 `<modules>` 注册、`ruoyi-admin` 增加对该模块的依赖，并配置 MyBatis 扫描路径（`MapperScan`）— 属于架构变更，建议在 `docs/adr/` 留一条决策记录。

### 4.1 第一个可验证的「列表」API 示例（需登录态）

当前后端 `context-path` 为 `/`，端口 `8080`。农业模块接口多为若依统一前缀 `**/prod-api`**（以前端代理为准；若本地直连后端，请以 `frontend/admin-web/vue.config.js` 中 `devServer.proxy` 配置为准）。

**代码参考（Controller 路径）：**

```38:55:apps/qiyuan-backend/ruoyi-admin/src/main/java/com/ruoyi/web/controller/agri/AgriBrandTracePageController.java
@RestController
@RequestMapping("/agri/brandTrace")
public class AgriBrandTracePageController extends BaseController
{
    // ...
    @PreAuthorize("@ss.hasPermi('agri:brandTrace:list')")
    @GetMapping("/list")
    public TableDataInfo list(AgriBrandTracePage agriBrandTracePage)
    {
        startPage();
        List<AgriBrandTracePage> list = agriBrandTracePageService.selectAgriBrandTracePageList(agriBrandTracePage);
        return getDataTable(list);
    }
```

**建议验证步骤（命令）：**

```powershell
# 1）启动后端
cd F:\chuangye\apps\qiyuan-backend
mvn -pl ruoyi-admin -am spring-boot:run

# 2）启动前端（另开终端）
cd F:\chuangye\frontend\admin-web
npm install
npm run dev
```

浏览器访问前端登录后，打开「品牌溯源」相关菜单触发列表请求；或使用 Swagger（若已启用）：查看 `ruoyi-admin` 中 springdoc 配置对应 URL。

**权限说明：** `agri:brandTrace:list` 需在数据库菜单/角色中授予当前用户；若 403，先在「系统管理 → 菜单/角色」中核对权限字符与路由。
